# Phase 5b - closing the Phase 5 limitations

No Phase 5 result file, model or embedding file was overwritten: new artefacts have a `_v2` suffix, a new seed number or a new file name, and `embeddings_skills.npz` is byte-for-byte the Phase 5 original.  Only GENERATED / descriptive files changed: `docs/phase5_report.md` and its charts (regenerated by `report_dl.py`, now over seeds 42-46 and with the Phase 5b notes), `docs/DEEP_LEARNING.md` and `docs/HANDOFF.md` (wording and numbers).

## Limitation 1 - MyCareersFuture was missing from the autoencoder work  ->  FIXED (with a caveat)
The original MCF repository now returns 404; a GitHub fork with the same layout and the same 20,298 postings works (`AKBakshay/JD2Skills-BERT-XMLC`; the contents were not byte-compared with the original).

**Step 1 - what do the Phase 5 autoencoders do on MCF? (`scripts/extend_dl_to_mcf.py`, zero-shot, nothing retrained)**  They transfer **poorly**:

| on MCF test jobs (4,110 jobs, split by employer) | recall@10 of dropped skills |
|---|---|
| Phase 5 denoising AE (never saw MCF) | 0.245 |
| Phase 5 basic AE | 0.221 |
| popularity fitted on MCF train | 0.259 |
| co-occurrence fitted on MCF train | 0.476 |

Denoising minus co-occurrence -0.2306 [-0.2460, -0.2157].  k-NN category purity on MCF: raw skills 0.459, denoising latent 0.364.
So simply appending MCF embeddings produced by the Phase 5 model would have added weak vectors; that file was NOT kept (the original `embeddings_skills.npz` is restored).

**Step 2 - retrain WITH MCF (`scripts/train_autoencoder_v2.py`)** - Phase 5's own training / evaluation code and protocol, on a database that includes MCF (38,407 train / 11,598 test jobs, 1,500 skills, latent 64, split by employer, seed 42):

| model | recall@10 v1 (Phase 5, no MCF) | recall@10 v2 (with MCF) |
|---|---|---|
| denoising AE | 0.307 | 0.405 |
| deep AE | 0.295 | 0.386 |
| basic AE | 0.257 | 0.322 |
| co-occurrence baseline | 0.303 | 0.348 |
| popularity baseline | 0.182 | 0.173 |

Paired recall@10 difference, denoising minus co-occurrence (employer-clustered bootstrap): v1 +0.0040 [-0.0024, +0.0106] (a tie); **v2 +0.0565 [+0.0489, +0.0643]** (supported).  Deep minus co-occurrence +0.0380 [+0.0302, +0.0457]; basic minus co-occurrence -0.0268 [-0.0356, -0.0171] (the basic AE does NOT beat the baseline).
By source (denoising / co-occurrence / popularity): emscad 0.225 / 0.206 / 0.136; linkedin 0.327 / 0.288 / 0.195; mcf 0.581 / 0.511 / 0.188; naukri 0.401 / 0.304 / 0.168.
k-NN purity on EMSCAD labels (chance 0.137): raw 0.396, denoising 0.439.

**Caveats (read before comparing v1 with v2):** the v2 database was rebuilt in the Phase 6 session WITHOUT O*NET (its Excel files were not available), so the skill inventory, vocabulary and splits differ from Phase 5's; v2 is a single seed; the improvement over co-occurrence is real within v2, but "v2 beats v1" is not a like-for-like claim.

## Limitation 2 - the DL signal could not cover most sources  ->  FIXED
`embeddings_skills_v2.npz` (`scripts/build_dl_embeddings_v2.py`, keyed by (source, external_id)) covers 59,748 jobs of all four sources (mcf 18,732, emscad 15,529, linkedin 13,692, naukri 11,795).  `jobintel/rec/dlsim.py::DLSkillSimilarity` turns a profile's skills into the same latent space; jobs without an embedding score neutrally (neither penalised nor boosted) and the coverage is reported.  The recurrent text-space embeddings (EMSCAD only) are a different space and are not mixed in.

## Limitation 4 - only 2 seeds  ->  FIXED (5 seeds per recurrent model)
