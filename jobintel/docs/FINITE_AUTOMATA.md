# Finite automata in the project (IR syllabus: *Finite automata and language models*)

Two kinds of automata are implemented **from scratch** in `jobintel/processing/fsa.py` and used in `patterns.py`.

## 1. TokenNFA - pattern recognition over a token stream
A non-deterministic finite automaton whose transitions are *token-class predicates* (NUM, YEAR-WORD, CURRENCY, DEGREE-LEVEL ...).
It is simulated with the classical "set of current states" algorithm (an implicit subset construction), scanning every start
position and keeping the leftmost-longest non-overlapping match. A small *semantic action* then converts the matched tokens to values
(`3-5 years` -> min 3, max 5). Ambiguous matches are guarded by context (a bare `2 years` counts only near *experience/required/...*).

| automaton | states | transitions | state diagram (Graphviz) |
|---|---|---|---|
| experience | 13 | 21 | `docs/fsa/experience.dot` |
| degree | 11 | 13 | `docs/fsa/degree.dot` |
| salary | 18 | 31 | `docs/fsa/salary.dot` |
| certification | 12 | 13 | `docs/fsa/certification.dot` |
| job_role | 8 | 13 | `docs/fsa/job_role.dot` |

Experience automaton (simplified):
```
q0 --QUALIFIER--> qQ --NUM--> qN1 --'+'--> qPlus --YEAR--> qY* (exp_bare)
q0 ---------NUM-------------> qN1 --('-'|'to')--> qDash --NUM--> qN2 --YEAR--> qY* --('of')--> qOf --EXP--> qExp** (exp_explicit)
                                                                                 \------------EXP---------> qExp**
```
(`*` / `**` = accepting states; `exp_explicit` beats `exp_bare`.)

## 2. AhoCorasick - dictionary matching
A trie turned into a deterministic automaton with failure links; one left-to-right pass finds every skill / city / employment-type /
seniority phrase regardless of dictionary size. The skill automaton built from the current lexicon has **3,418 phrases / 5,094 states**;
the location automaton knows **211** place names (learned from the ingested jobs). Matches are resolved with maximal munch;
punctuation other than `-` and `/` is a barrier (`machine, learning` is not `machine learning`).

## Where they are used
* **ingestion** (`ingest/load_db.py`): fills missing experience, education, salary, employment type and skills of every job from its text; the salary automaton also parses the MyCareersFuture salary strings;
* **query processing** (Phase 2): `Entry level machine learning jobs in Pune` -> level + skill + location;
* **resume analysis / NER** (Phase 5): the skill automaton seeds the spaCy EntityRuler.

## Limits (stated honestly)
Finite automata recognise **surface patterns only**. They do not understand meaning ("not required: Python" would still yield the skill Python),
do not resolve synonyms beyond the lexicon, and need maintenance when wording changes. Semantic matching is the job of the language models,
the knowledge base and the deep-learning components.
